01 · Business Problem

Can we forecast demand accurately enough to change inventory decisions?

The Superstore dataset already revealed in the Excel analysis that the business has a significant seasonal demand pattern — Q4 spikes, category-specific peaks, and regional variation. The next question is whether that pattern is predictable enough to act on.

The business case is straightforward: every stockout during a demand peak is lost revenue. Every overstock between peaks is tied-up cash and write-down risk. A demand forecast that is "usefully accurate" — not perfect, but directionally reliable — changes both inventory and purchasing decisions.

The honest framing: Forecasting is not about predicting the future precisely. It is about reducing the range of uncertainty enough to make better decisions. A forecast that narrows the inventory planning range from "we don't know" to "somewhere between X and 1.3X" is already valuable — even if it is never exactly right.
02 · Dataset

Superstore dataset — building on the Excel analysis

This project uses the same Superstore dataset as the Excel Sales Analysis, giving a direct before-and-after comparison: what the Excel dashboard revealed descriptively vs. what the Python forecasting model can project forward.

The dataset contains 9,994 order records with order dates, product categories, sub-categories, regions, quantities, and sales values. The time dimension (order date) is the key field that makes forecasting possible — it provides the historical demand signal the model learns from.

04 · Methodology

How the forecasting model is being built

1
Time-series aggregation
Aggregate daily order records into monthly totals using Pandas groupby and resample. Create separate time series for total demand, by-category demand, and by-region demand.
2
Decomposition — trend, seasonality, residual
Use statsmodels seasonal decomposition to separate the demand signal into its three components. This tells us how much of the Q4 spike is genuine seasonality vs. trend growth vs. random noise.
3
Baseline forecast — moving average
Build a simple 3-month moving average as the baseline. This is the "naive" model that more sophisticated methods need to beat. If a complex model can't beat a moving average, the complexity is not justified.
4
Improved forecast — exponential smoothing
Apply Holt-Winters exponential smoothing, which accounts for both trend and seasonality — a more appropriate method for the Superstore data where both are clearly present.
5
Accuracy evaluation — holdout period
Split the data: train on the first 3.5 years, test on the final 6 months. Compare RMSE for the moving average and exponential smoothing models to select the better performer.
6
Business interpretation
Translate forecast numbers into planning actions: what inventory level to hold in October to prepare for November-December peak, what safety stock to add for high-volatility categories.

Sample code — monthly aggregation and seasonal decomposition:

# Load and prepare the Superstore dataset
import pandas as pd
import matplotlib.pyplot as plt
from statsmodels.tsa.seasonal import seasonal_decompose

# Load data and parse dates
df = pd.read_csv('superstore.csv', parse_dates=['Order Date'])
df.rename(columns={'Order Date': 'order_date',
                    'Sales': 'sales'}, inplace=True)

# Aggregate to monthly total sales
monthly = (df.set_index('order_date')
             ['sales']
             .resample('MS')  # month start frequency
             .sum()
             .reset_index())

# Seasonal decomposition
decomp = seasonal_decompose(
    monthly.set_index('order_date')['sales'],
    model='additive',
    period=12
)

# Plot components: trend, seasonal, residual
decomp.plot()
plt.tight_layout()
plt.show()
05 · Why Python for This

What Python adds that Excel cannot

Statistical forecasting models
Excel can compute moving averages but cannot natively implement Holt-Winters exponential smoothing with automatic seasonality detection. Python's statsmodels library handles this properly.
Reproducible, automated pipeline
A Python script can re-run the entire forecast with new data in seconds. Excel requires manual pivot table refresh and chart recreation. For ongoing demand planning, Python scales and Excel doesn't.
Accuracy measurement
Python calculates RMSE, MAE, and MAPE automatically for model comparison. Excel would require manual formula construction across multiple sheets — error-prone and not scalable.
Documented analysis in Jupyter
Jupyter Notebook combines code, output, and written explanation in one document. This makes the analysis reviewable by both technical and non-technical stakeholders — essential for business use.
